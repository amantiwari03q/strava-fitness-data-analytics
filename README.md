# strava-fitness-data-analytics
🏃 Fitness Tracker Data Analytics — SQL, Python EDA & Streamlit

End-to-end data analytics case study using Fitbit fitness-tracker data, with SQL analysis, Python EDA, an interactive Streamlit dashboard, and business/marketing insights.

📌 Project Overview

This project analyzes daily fitness-tracker data to understand activity, sedentary behavior, sleep, calorie burn, tracker engagement, and user segments.

The analysis follows a complete analytics workflow:

Raw CSV → Data Cleaning & Feature Engineering → SQL Analysis → Python EDA → Interactive Streamlit Dashboard → Business Insights

The repository is named strava-fitness-data-analytics, but the implemented case study uses Fitbit data in a Bellabeat-style marketing analytics context. The Streamlit application explicitly describes the dataset as 33 Fitbit users covering April 12 to May 12, 2016.

🎯 Business Problem

The core business question is:

How are consumers using fitness trackers, and what product/marketing opportunities can be identified from their activity and wellness behavior?

The project focuses on questions such as:

How active are users on average?

Which weekdays show higher or lower activity?

How much time do users spend sedentary?

How many days reach the 10,000-step benchmark?

What are the major user activity segments?

How does activity relate to sleep?

How consistently do users wear the tracker?

Which wellness features show adoption?

What insights can support engagement-focused marketing?

📊 Dataset

Source: Fitbit daily fitness-tracker dataset

Granularity: One row per user per day

Study period: April 12, 2016 – May 12, 2016

Users: 33

Rows: 940

Main domains: activity, distance, calories, sleep, weight/BMI, heart rate and intensity
